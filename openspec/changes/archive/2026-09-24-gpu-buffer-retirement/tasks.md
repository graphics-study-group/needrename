## 1. Retirement facility core

- [x] 1.1 Give `BufferAllocation` an optional hand-off to the epoch tracker and `AllocatorState` a setter that installs it: the destructor hands the allocation to the tracker when one is installed, and otherwise destroys it as today. There is no sink interface between them — the tracker is the only recipient of retired allocations, so no other allocation manager is implied. Verify: a unit test installs the tracker on the allocator, destroys an allocation, and observes exactly one hand-off and no `vmaDestroyBuffer` call; a second test without the tracker installed observes immediate destruction.
- [x] 1.2 Implement the tracker's knowledge model: monotonic watermark issue, the **set of individually reported epochs**, and the **completed prefix** derived from it by advancing through the contiguous run of reports. A report proves only the epoch it names; the prefix must not be advanced by a report for a later epoch (design D2, D3). Verify: unit tests cover a report for a later epoch leaving the prefix untouched, and the prefix advancing in one step once every epoch up to some watermark has been reported.
- [x] 1.3 Implement both parking modes and their release conditions, evaluated when a resource is parked and again after every report (design D4): the **upper-bound mode** (referencing epochs ⊆ {≤ bound}; release when the prefix reaches the bound; the default for `~BufferAllocation`, bound = newest watermark at release time) and the **exact mode** (the caller names the single referencing epoch; release when that epoch is reported). Verify: unit tests cover upper-bound release only when the prefix arrives; exact release on that epoch's own report without the prefix; a resource bound into a recorded-but-unsubmitted command buffer not being released early; an exact claim naming an unreported epoch being retained rather than trusted; and a condition already satisfied at park time releasing immediately.
- [x] 1.4 Implement epoch termination: reporting (after the submitter observes a completion signal) and abandonment, where abandonment marks an epoch as reported **without** releasing anything directly and is valid only for epochs with no issued submission (design D7). Verify: a unit test asserts that resources parked under an abandoned epoch survive while an earlier epoch is unreported, and are released only once the prefix reaches them.
- [x] 1.5 Add debug observability: counters for parked items, outstanding epochs and the prefix, an assertion bounding outstanding epochs, and the one-tracker-per-device assertion (register on construction, unregister on destruction, keyed by device handle — design D6). Verify: counters are queryable in a unit test; the outstanding-epoch assertion fires in a test that opens epochs without terminating them; and the singleton assertion fires in a test that constructs a second tracker for the same device.
- [x] 1.6 Wire ownership: `DeviceContext` owns the tracker (declared so it is destroyed before the allocator), `AllocatorState` gains a setter for the tracker, and `DeviceContext` installs it after constructing the allocator. Verify: a headless test creates a `DeviceContext`, allocates and destroys buffers, and tears down without validation errors; the tracker's teardown releases anything still parked.
- [x] 1.7 Keep the standalone path working: `test/unit/rhi/submission_helper_test.cpp` constructs its own tracker next to the `DeviceInterface` and `AllocatorState` it already builds, and `test/unit/rhi/rhi_standalone_test.cpp` is left unchanged (it does not defer work, so it needs no tracker). Verify: both unit tests build and pass, and `Rhi/SubmissionHelper.h` still depends on neither `Render/RenderSystem.h` nor `FrameSemaphore.hpp` — note that `rhi_standalone_test.cpp` already includes a `Render/Asset/` header, which the module requirement does not forbid.

## 2. Submitter integration

- [x] 2.1 Make `SubmissionHelper` a driver: take the tracker as a construction dependency, **open its own epoch for each submission it issues**, wait that submission's fence, report that epoch, and release the batch's staging under the exact mode naming that epoch (design D8, D9). It must not report an epoch it did not open — in particular it must not report the frame's epoch on `OnBatchComplete`, whose fence says nothing about the frame's main batch. Verify: `submission_helper_test` passes with the tracker added in task 1.7; a test asserts that a blocking submission leaves zero parked items after it returns; and a test asserts that staging released after the deferred batch's fence wait is not retained beyond that wait.
- [x] 2.2 Make `FrameManager` a driver: store a watermark per in-flight slot, open the frame's epoch at the end of a successful `StartFrame` (after acquisition and command-buffer reset, design D7), and report it after the slot's fence wait. Verify: a windowed or headless run under the validation layer reports no use-after-free, and a skipped frame (simulated acquisition failure) leaves no open epoch.
- [x] 2.3 Release parked resources at every device-idle point: `RenderSystem::WaitForIdle`, the physics-app idle waits, and test teardown. This releases retired allocations only — it must not be wired to anything that owns live resources. Verify: `grep` for device-idle call sites shows each one paired with the release, and a headless test asserts parked items reach zero after an idle wait while a still-live buffer is untouched.

## 3. Stable ownership of model matrices

- [x] 3.1 Add a shared-ownership buffer factory alongside `CreateUnique` and confirm the buffer types remain usable everywhere a unique-ownership buffer is used. Verify: a unit test creates a shared buffer, binds it through the existing binding path, and observes the allocation alive while a reference is held.
- [x] 3.2 Make `PhysicsScene` hold its model matrices buffer by shared ownership and expose it from `GetGpuBuffers()` without leaking ownership rules to the caller. Verify: `PhysicsScene` resizes its buffers and the previously exposed handle remains valid while a reference is held.
- [x] 3.3 Convert the render-side consumers to a stable reference: `SceneDataManager::SetModelMatricesBuffer` / `GetModelMatricesBuffer`, `ComplexRenderGraphBuilder::BuildDefaultRenderGraph`, `EditorRenderGraphBuilder::BuildEditorRenderGraph`, and the `MainClass` forwarding call. Verify: the project builds and a windowed run renders physics-driven model matrices with no dangling reference reported by the validation layer.
- [x] 3.4 Verify the reallocation scenario end to end: change the rigid body slot count after the render graph has been built. Verify: a test or instrumented run shows the graph still referencing a live buffer, and the previously forwarded buffer is released only after it is unreferenced.

## 4. Verification

- [x] 4.1 Build a headless fixture that drives a physics scene with geometry changes between steps and runs several frames with two to three frames in flight. Verify: it runs under the validation layer with no use-after-free or invalid-handle report.
- [x] 4.2 Extend the fixture to a long dynamic run with repeated grow/shrink of the shape and body counts. Verify: the parked-item counter is non-monotonic (it returns to zero after idle waits) and device memory does not grow without bound.
- [x] 4.3 Run the full suite for both configurations. Verify: `cmake --build --preset msvc-debug` then `ctest --preset msvc-debug` pass, and `openspec validate gpu-buffer-retirement` reports the change valid.
