## 1. Arena core

- [ ] 1.1 Implement the resident content-keyed cache: key on `(descriptor-set layout, dynamic-offset flags, resolved binding entries)`, record the acquiring epoch and the acquisition order on each entry, record which pool served it so releases return there, obtain layouts through the immutable resource cache, name pools and sets for debugging, and expose counters for live pools, resident entries, and entries held back by the epoch guard. Verify: unit tests cover a repeated identical request returning the same set within one epoch and across epochs, two entries with different content coexisting, a released set returning to the pool that served it, and acquisition past one pool's capacity succeeding with an additional pool.
- [ ] 1.2 Implement the epoch guard and the pinning rule: entries acquired while no epoch is open are marked unclaimed and are never evictable; the first epoch to open afterwards claims them and records itself against them; an entry is eligible only when claimed and its recorded epoch is at or below the completed **prefix**. A report for the entry's own epoch must NOT make it eligible — earlier epochs may still bind the same set. Use a distinct unclaimed state rather than a zero epoch value. Verify: unit tests assert that an unclaimed entry survives eviction pressure, that a claim makes it eligible only once the prefix passes that epoch (not when the epoch itself is reported), and that an entry recorded against a zero value would have been wrongly eligible (the regression this state exists to prevent).
- [ ] 1.3 Implement pressure-driven eviction: when the resident count exceeds the configured budget, release the least recently acquired **eligible** entries; if none are eligible, exceed the budget and report the excess through the counters. Verify: unit tests cover eviction down to the budget, no eviction when every entry is outstanding, and the resident count returning to at or below the budget once the prefix advances past the entries' recorded epochs.
- [ ] 1.4 Register the arena with the preceding change's completed-prefix advancement — the arena observes exactly that one event, not begin/submit/complete/drain, and not individual reports — and make a device-idle wait a no-op for the cache beyond advancing the prefix. Verify: unit tests assert that an idle wait alone releases nothing, that a report for an epoch does not by itself make its entries eligible, and that the same binding content recorded after an idle wait reuses its entry.
- [ ] 1.5 Wire `DeviceContext`: own the arena, declare it before the retirement tracker so the tracker cannot outlive its observer, and register it as the prefix observer. Verify: a headless test constructs a `DeviceContext`, acquires sets across epochs, and tears down with entries still resident under the validation layer without errors.

## 2. Compute path onto the pressure-driven trigger

- [ ] 2.1 Make `ComputeStage` stop creating and exposing a descriptor pool while keeping its pipeline, pipeline layout and descriptor set layout, and move the pool's debug naming to the arena. Verify: the stage instantiates from SPIR-V with no pool created under the validation layer, and no caller references the removed pool accessor.
- [ ] 2.2 Make `ComputeResourceBinding` acquire its sets from the arena instead of a caller-supplied pool, keeping `slot_count` as the size of the uniform-buffer slice set and the bound on accepted slot values, with no descriptor set allocated at construction. Verify: a binding created with `slot_count = 3` allocates three uniform-buffer slices and zero descriptor sets until asked, and the first `UpdateGPUInfo` obtains its set from the arena.
- [ ] 2.3 Confirm the existing consumers are untouched: every `AllocateResourceBinding`, `BindBuffer`, `BindComputeResource` and `DispatchCompute` call site keeps compiling and running without edits, and each dispatch re-acquires its sets (the contract in the capability spec). Verify: the headless algorithm and capacity tests pass, and a windowed bloom run reports no binding-related validation errors.

## 3. Material, scene and camera paths onto the owner-driven trigger

- [ ] 3.1 Make `ShaderResourceBinding` acquire owner-driven sets from the arena, drop its caller-supplied pool parameter, and bound its content cache with an eviction that releases through the arena (deferred when the entry's epoch is still outstanding). Verify: unit tests cover reuse of a cached set across repeated calls, eviction releasing a set rather than freeing it immediately, and destruction releasing every set the binding still holds.
- [ ] 3.2 Update the material call site (`MaterialInstance::UpdateGPUInfo`) and confirm the per-pass per-slot set cache still works unchanged. Verify: a rendered scene is unchanged, and `GetDescriptor(tpl, backbuffer)` returns a valid set on the frame after `UpdateGPUInfo`.
- [ ] 3.3 Remove the per-template descriptor pool from `MaterialTemplate` / `MaterialLibrary`, replace the `if (b.descriptor_pool)` sentinel with a layout-derived condition, and let the arena own pool naming. Verify: the project builds, a scene with several material templates renders correctly, and a template without material descriptors still takes its no-material-descriptors path.
- [ ] 3.4 Move `SceneDataManager`'s and `CameraManager`'s descriptor pools onto the arena as owner-driven sets, so that no consumer in the repository creates a pool. Verify: a windowed run renders correctly, and a repository search finds no descriptor-pool creation outside the arena.

## 4. Verification

- [ ] 4.1 Add a steady-state reuse fixture that dispatches the same compute work across several epochs on the pipelined driver shape. Verify: after the first epoch the minted-set counter stops increasing, and the live set count stays flat instead of growing.
- [ ] 4.2 Add a fully-serialised fixture that completes each epoch before opening the next (the physics-app shape, which is what defeated the earlier age-driven release rule). Verify: its sets are reused across epochs rather than re-minted, and nothing is released while the arena is within budget.
- [ ] 4.3 Add a growth fixture that acquires more sets with distinct content than the previous per-consumer budget allowed, and an eviction fixture that applies pressure while entries are still outstanding. Verify: every acquisition succeeds with additional pools created; ineligible entries are not released and the budget is exceeded rather than violated; eligible entries are evicted down to the budget.
- [ ] 4.4 Add pinning fixtures for the record-then-submit shapes: two consecutive record-and-submit rounds with no epoch open at recording time, and a batch that is recorded but never submitted. Verify: in both cases no set is released while a recorded command buffer can still reference it, and the never-submitted batch's sets are released only when the arena is destroyed.
- [ ] 4.5 Add a material churn fixture that creates and destroys material instances which rebind textures. Verify: the live owner-driven set count returns to its baseline after the instances are destroyed.
- [ ] 4.6 Run the full suite for both configurations. Verify: `cmake --build --preset msvc-debug` then `ctest --preset msvc-debug` pass, and `openspec validate descriptor-arena-epoch-buckets` reports the change valid.
