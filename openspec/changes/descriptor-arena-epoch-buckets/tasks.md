## 1. Arena core

- [ ] 1.1 Implement the **pool layer**: create pools with `eFreeDescriptorSet`, grow on demand when a request cannot be served (retrying once against a fresh pool on an out-of-pool-memory result), remember which pool served each set so releases return there, resolve descriptor-set layouts through the immutable resource cache, name pools and sets for debugging, and expose counters for live pools and live sets. Verify: unit tests cover acquiring past one pool's capacity with an additional pool created, and a released set returning to the pool that served it.
- [ ] 1.2 Implement the **cache layer**: key on `(descriptor-set layout handle, dynamic-offset flags and set id, resolved binding entries)`, build the descriptor writes and call `updateDescriptorSets` on a miss, record the acquiring epoch, the acquisition order and the serving pool on each entry, expose counters for resident entries and for entries held back by the epoch guard, and never rewrite a resident entry's descriptors. Verify: unit tests cover a repeated identical request returning the same set within one epoch and across epochs, two entries with different content coexisting, a repeated request of the same layout with different content minting a distinct set, and the counter for entries held back by the guard moving when an entry is ineligible.
- [ ] 1.3 Make `ShaderResourceBinding` the resolver in front of the cache layer: it keeps the `name -> resource` map and maps names onto the reflected layout, hands the arena the resolved entries, and loses its own content cache and its `pool` parameter. Verify: unit tests cover reuse of a resolved set across repeated calls and that the layout is resolved from the resource cache rather than from the `SPLayout` object's address.
- [ ] 1.4 Implement the epoch guard and the pinning rule: entries acquired while no epoch is open are marked unclaimed and are never evictable; the first epoch to open afterwards claims them and records itself against them; an entry is eligible only when claimed and its recorded epoch is at or below the **read** completed prefix. Reading the prefix, not subscribing to it, is the whole mechanism — nothing registers with the tracker. A report for the entry's own epoch must NOT make it eligible. Use a distinct unclaimed state rather than a zero epoch value. Verify: unit tests assert that an unclaimed entry survives eviction pressure, that a claim makes it eligible only once the prefix passes that epoch (not when the epoch itself is reported), that eligibility is observed on the next arena call after the prefix advances, and that an entry recorded against a zero value would have been wrongly eligible (the regression this state exists to prevent).
- [ ] 1.5 Implement pressure-driven eviction: when the resident count exceeds the configured budget, release the least recently acquired **eligible** entries; if none are eligible, exceed the budget and report the excess through the counters. There is no other release path: no owner release entry point exists. Verify: unit tests cover eviction down to the budget, no eviction when every entry is outstanding, and the resident count returning to at or below the budget once the prefix advances past the entries' recorded epochs.
- [ ] 1.6 Implement the **pool-layer acquisition for sets the caller writes**: allocate a set for a layout and return it, knowing nothing about its contents, never interning it and never reclaiming it; provide no release entry point, because both consumers outlive the arena and are bounded by structural constants. Verify: unit tests assert that two requests for the same layout return distinct sets, that such a set is unaffected by eviction pressure, and that it remains valid until the arena is destroyed.
- [ ] 1.7 Wire `DeviceContext`: own the arena, declare it before the retirement tracker so it is destroyed after the tracker and before the immutable resource cache and the device, and add `DeviceContext::WaitForIdle()` performing `waitIdle` + `EpochTracker::ReleaseAllParked` + `DescriptorArena::OnDeviceIdle`, with `OnDeviceIdle` recording `max(GetNewestWatermark())` as the idle watermark and releasing nothing. Make `RenderSystem::WaitForIdle` delegate to it. Verify: a headless test constructs a `DeviceContext`, acquires sets across epochs, and tears down with entries still resident under the validation layer without errors; unit tests assert that an idle wait alone releases nothing, that a report for an epoch does not by itself make its entries eligible, that an idle wait makes eligible entries reclaimable by a subsequent over-budget acquisition, that an entry acquired after the idle wait stays ineligible, and that the same binding content recorded after an idle wait reuses its entry.

## 2. Compute path onto the cache layer

- [ ] 2.1 Make `ComputeStage` stop creating and exposing a descriptor pool while keeping its pipeline, pipeline layout and descriptor set layout, create that layout through the immutable resource cache (as `MaterialLibrary` does) so the pipeline's layout and the allocation layout are one object, and move the pool's debug naming to the arena. Verify: the stage instantiates from SPIR-V with no pool created under the validation layer, no caller references the removed pool accessor, and the layout the stage exposes is the object the resource cache returns for the same description.
- [ ] 2.2 Make `ComputeResourceBinding` acquire its sets from the arena instead of a caller-supplied pool, keeping `slot_count` as the size of the uniform-buffer slice set and the bound on accepted slot values, deleting the per-slot handle array, and changing `UpdateGPUInfo` to return the slot's descriptor set together with its dynamic offsets (dropping the `const noexcept` that the allocation path could violate). Verify: a binding created with `slot_count = 3` allocates three uniform-buffer slices and no descriptor set until asked, the first `UpdateGPUInfo` obtains its set from the arena, and no stored handle survives the call.
- [ ] 2.3 Confirm the existing consumers are untouched: every `AllocateResourceBinding`, `BindBuffer`, `BindComputeResource` and `DispatchCompute` call site keeps compiling and running without edits, and every use of a binding re-acquires its sets (the contract in the capability spec). Verify: the headless algorithm and capacity tests pass, and a windowed bloom run reports no binding-related validation errors.

## 3. Material path onto the cache layer

- [ ] 3.1 Update the material call site (`MaterialInstance::UpdateGPUInfo` and its callers in `CommandBuffer::BindMaterial` and `SceneDataManager::DrawSkybox`): return the set together with the dynamic offsets, delete the per-pass handle array and `GetDescriptor`, and refresh the set on every bind so the arena's recorded epoch stays an upper bound. Verify: a rendered scene is unchanged, and the descriptor bound on a frame is the one acquired in that frame.
- [ ] 3.2 Replace the three pool-derived facts in `MaterialTemplate` / `MaterialLibrary` with one cached layout-derived boolean: the branch sentinel in `MaterialLibrary::CreatePipeline`, `MaterialTemplate::GetDescriptorPool()` (removed), and `MaterialTemplate::HasMaterialData()`, and remove the log that tests the pool before assigning it. Compute the boolean once at construction from the reflected layout — not per frame, because `GenerateLayoutBindings` allocates. Verify: the project builds, a scene with several material templates renders correctly, and a template without material descriptors still takes its no-material-descriptors path.
- [ ] 3.3 Delete the pool vocabulary that has no other user: `PipelineInfo::PoolInfo`, `PipelineInfo::MaterialPoolInfo` and the `MaterialTemplate::PoolInfo` alias. Verify: a repository search finds no reference to `MaterialPoolInfo`, `PoolInfo` or `MAX_SET_SIZE`.

## 4. Scene, camera and the last pool

- [ ] 4.1 Move `SceneDataManager`'s descriptor sets onto the arena's pool layer: obtain its per-in-flight sets and layout through the arena instead of a pool it creates, keep writing binding 1 and binding 2 itself each frame, and record the obligation not to rewrite a set while a command buffer that binds it may still be executing. Verify: a windowed run renders correctly, and the manager's sets are unchanged across frames.
- [ ] 4.2 Move `CameraManager`'s descriptor sets onto the arena's pool layer the same way. Verify: a windowed run renders correctly, the camera descriptor set is valid for every in-flight slot, and the manager creates no pool.
- [ ] 4.3 Confirm that no consumer in the repository creates a descriptor pool except the ImGui backend, whose pool is the stated exception because the GUI library allocates and frees its own sets. Verify: a repository search for descriptor-pool creation finds only the arena and `GUISystem`.

## 5. Verification

- [ ] 5.1 Add a steady-state reuse fixture that dispatches the same compute work across several epochs on the pipelined driver shape. Verify: after the first epoch the minted-set counter stops increasing, and the live set count stays flat instead of growing.
- [ ] 5.2 Add a fully-serialised fixture that completes each epoch before opening the next (the physics-app shape, which is what defeated the earlier age-driven release rule). Verify: its sets are reused across epochs rather than re-minted, and nothing is released while the arena is within budget.
- [ ] 5.3 Add a growth fixture that acquires more sets with distinct content than the previous per-consumer budget allowed, and an eviction fixture that applies pressure while entries are still outstanding. Verify: every acquisition succeeds with additional pools created; ineligible entries are not released and the budget is exceeded rather than violated; eligible entries are evicted down to the budget.
- [ ] 5.4 Add pinning fixtures for the record-then-submit shapes: two consecutive record-and-submit rounds with no epoch open at recording time, and a batch that is recorded but never submitted. Verify: in both cases no set is released while a recorded command buffer can still reference it, and the never-submitted batch's sets are released only when the arena is destroyed.
- [ ] 5.5 Add a material churn fixture that creates and destroys material instances which rebind textures, and then applies eviction pressure. Verify: the live set count returns to its baseline once pressure is applied and the completed prefix has passed the destroyed instances' entries — reclamation is lazy by design, so destroying the instances alone is not expected to change the count.
- [ ] 5.6 Add a device-idle fixture: acquire sets, wait the device idle, and acquire the same content again. Verify: the idle wait releases nothing, the same sets are reused, and a subsequent over-budget acquisition can reclaim the entries the idle wait made eligible.
- [ ] 5.7 Run the full suite for both configurations. Verify: `cmake --build --preset msvc-debug` then `ctest --preset msvc-debug` pass, and `openspec validate descriptor-arena-epoch-buckets` reports the change valid.
