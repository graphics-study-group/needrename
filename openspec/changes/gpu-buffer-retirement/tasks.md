## 1. Retirement facility core

- [ ] 1.1 Add the allocation retire sink interface on the Buffer side (a single virtual hand-off entry point) and give `BufferAllocation` an optional sink: its destructor hands the allocation to the sink when one is set, and otherwise destroys it as today. Verify: a unit test constructs a `BufferAllocation` with a recording sink, destroys it, and observes exactly one hand-off and no `vmaDestroyBuffer` call; a second test without a sink observes immediate destruction.
- [ ] 1.2 Implement the epoch tracker: monotonic watermark issue, outstanding set, contiguous-prefix completion advance, park map keyed by the release-time watermark, device-idle release of parked items, and `AbortEpoch`. The parking watermark is the newest outstanding epoch at the moment of release — it must not depend on when the allocation was created or last bound (design D4). Verify: unit tests cover release once the completed watermark reaches the parking watermark, out-of-order completion retaining an earlier epoch's resources, release deferred while a command buffer that bound the allocation is recorded but not yet submitted, immediate release when the parking watermark is already complete, and `AbortEpoch` releasing everything parked under the abandoned epoch.
- [ ] 1.3 Add debug observability: counters for parked items and outstanding watermarks, an assertion bounding outstanding watermarks, and the one-tracker-per-device assertion (register on construction, unregister on destruction, keyed by device handle — design D6). Verify: counters are queryable in a unit test; the outstanding-watermark assertion fires in a test that opens epochs without reporting them; and the singleton assertion fires in a test that constructs a second tracker for the same device.
- [ ] 1.4 Wire ownership: `DeviceContext` owns the tracker (declared so it is destroyed before the allocator), `AllocatorState` gains a retire-sink setter, and `DeviceContext` installs the sink after constructing the allocator. Verify: a headless test creates a `DeviceContext`, allocates and destroys buffers, and tears down without validation errors; the tracker's teardown releases anything still parked.
- [ ] 1.5 Keep the standalone path working: `test/unit/rhi/submission_helper_test.cpp` constructs its own tracker next to the `DeviceInterface` and `AllocatorState` it already builds, and `test/unit/rhi/rhi_standalone_test.cpp` is left unchanged (it does not defer work, so it needs no tracker). Verify: both unit tests build and pass, and neither includes a header from `engine/Render/`.

## 2. Submitter integration

- [ ] 2.1 Make `SubmissionHelper` a driver: take the tracker as a construction dependency, open an epoch per submission, report completion after the fence wait and before releasing that batch's staging (design D9). Verify: `submission_helper_test` passes with the tracker added in task 1.5, and a new test asserts that a blocking submission leaves zero parked items after it returns.
- [ ] 2.2 Make `FrameManager` a driver: store a watermark per in-flight slot, open an epoch at the end of a successful `StartFrame` (after acquisition and command-buffer reset, design D7), report it complete after the slot's fence wait, and abort on the failure path. Verify: a windowed or headless run under the validation layer reports no use-after-free, and a skipped frame (simulated acquisition failure) leaves no open epoch.
- [ ] 2.3 Release parked items at every device-idle point: `RenderSystem::WaitForIdle`, the physics-app idle waits, and test teardown. This releases retired allocations only — it must not be wired to anything that owns live resources. Verify: `grep` for device-idle call sites shows each one paired with the release, and a headless test asserts parked items reach zero after an idle wait while a still-live buffer is untouched.

## 3. Stable ownership of model matrices

- [ ] 3.1 Add a shared-ownership buffer factory alongside `CreateUnique` and confirm the buffer types remain usable everywhere a unique-ownership buffer is used. Verify: a unit test creates a shared buffer, binds it through the existing binding path, and observes the allocation alive while a reference is held.
- [ ] 3.2 Make `PhysicsScene` hold its model matrices buffer by shared ownership and expose it from `GetGpuBuffers()` without leaking ownership rules to the caller. Verify: `PhysicsScene` resizes its buffers and the previously exposed handle remains valid while a reference is held.
- [ ] 3.3 Convert the render-side consumers to a stable reference: `SceneDataManager::SetModelMatricesBuffer` / `GetModelMatricesBuffer`, `ComplexRenderGraphBuilder::BuildDefaultRenderGraph`, `EditorRenderGraphBuilder::BuildEditorRenderGraph`, and the `MainClass` forwarding call. Verify: the project builds and a windowed run renders physics-driven model matrices with no dangling reference reported by the validation layer.
- [ ] 3.4 Verify the reallocation scenario end to end: change the rigid body slot count after the render graph has been built. Verify: a test or instrumented run shows the graph still referencing a live buffer, and the previously forwarded buffer is released only after it is unreferenced.

## 4. Verification

- [ ] 4.1 Build a headless fixture that drives a physics scene with geometry changes between steps and runs several frames with two to three frames in flight. Verify: it runs under the validation layer with no use-after-free or invalid-handle report.
- [ ] 4.2 Extend the fixture to a long dynamic run with repeated grow/shrink of the shape and body counts. Verify: the parked-item counter is non-monotonic (it returns to zero after idle waits) and device memory does not grow without bound.
- [ ] 4.3 Run the full suite for both configurations. Verify: `cmake --build --preset msvc-debug` then `ctest --preset msvc-debug` pass, and `openspec validate gpu-buffer-retirement` reports the change valid.
