## 8. Resource lifetime: sizing belongs to `PreGPUStep`

An earlier revision sized the hinge/fixed reduce groups inside `GPUStep` (a leftover of the `mode` design, where the group's `Ensure` was welded to the entry-build dispatch decision) and tracked geometry with three `cached_*` counters in the solver. That violated the solver's documented lifecycle — `PreGPUSolver.h` reserves `PreGPUStep` for "buffer sizing, CPU uploads", and `ISolver.h` states `PreGPUStep` runs outside the command-buffer scope — and the counters were only maintained for the joint groups: the contact group was created with `if (!contact_sort)` / `if (!contact_sum)`, so when `max_contact_point` (which tracks `shape_count`) changed between frames the `RadixSort`/`SumByKey` instances kept a stale capacity while the buffers and `pair_count` were resized. That threw out of `RadixSort::Record` when the capacity grew and silently reduced with the wrong channel stride when it shrank.

- [x] 8.1 Move every capacity-dependent `Ensure` for the hinge and fixed groups (reduce-group buffers, per-type lagrange buffers, `RadixSort`/`SumByKey` instances, `pair_count` constant) from `GPUStep` into `PreGPUStep`, so `GPUStep` contains no allocation and no host-visible write and only derives dispatch geometry.
- [x] 8.2 Delete `cached_hinge_count`, `cached_fixed_count` and `cached_body_count`; add `Impl::EnsureSortAndSum(sort, sum, capacity, body_count)` which asks the objects (`RadixSort::GetMaxElemCount`, `SumByKey::GetMaxEntries`, `SumByKey::GetMaxKeyValue`) whether they still match and rebuilds them otherwise, and route all three constraint types through it. The solver no longer keeps a shadow copy of state its resources already know.
- [x] 8.3 Pin the contract in the headless algorithm tests: `gpu_radix_primary_test` asserts `GetMaxElemCount()` reports the construction value and that `Record` rejects an `elem_capacity` above it; `gpu_sum_by_key_test` asserts `GetMaxEntries`/`GetMaxKeyValue`/`GetNumChannels`/`GetNumLevels` report the construction geometry and that no shader is loaded before the first `Record`.
- [x] 8.4 Rebuild and re-run the full suite (56/56 passed) and `openspec validate`.
